# Remaining limits

The implementation is a documented reconstruction, not an authenticated complete 2013 Live service. The recovered housing opcode set has known layouts and implemented paths, but that is not proof that every possible Live message and opaque field is understood. See [protocol boundaries](../protocol/PROTOCOL-BOUNDARIES.md).

Exact historical data remains unavailable for some trophy benefit tiers, costs and minimum levels, several capacities, original legal plot boundaries, some service appearances and other server-owned catalog values. Unknown trophy benefits are disabled. Explicit capacity/tariff/service defaults are labelled and do not become historical evidence when installed.

Only authenticated NPC furniture bindings are admitted. NPC quotas do not make an unreviewed plushie, pet or contract model usable. Holgresh uses an explicit original-model-default sizing policy because its historical raw height is unknown. Service assistants use documented original/basic-service appearance equivalents where the original contract appearance could not be recovered.

Legacy `IsScaling` experience now has a durable per-instance representation, separate from `character_evolving_items`, for the item and its scaling augments. Nonempty nested containers remain refused because the current native inventory integration has no second-level saved slot namespace. Other unsupported inventory shapes remain refused. See [item support](ITEM-SUPPORT.md) for exact boundaries.

The complete installer targets the pinned EQEmu source, MariaDB and a shared item/content/housing database. It includes Linux/AkkStack and native Windows paths. The Windows path has focused Windows-Python/Wine checks, but full MSVC compilation, native server startup and real NTFS permission/junction acceptance remain unverified. It refuses conflicting custom schemas, source records, unsupported engines and a custom guild-hall quest that has not been merged. Original client archives and matching collision maps must be supplied by the operator. It does not recreate an entire EQEmu distribution, silently migrate arbitrary split databases or import client assets from this repository.

Voluntary Move Out and return mechanisms are available. Existing properties are not automatically enrolled in destructive inactivity retirement, and an old guild's recipient is not guessed. Exact-generation policy/recipient checks remain required. Unknown commit outcomes require real supervised recovery; installation does not certify process death or discard pending custody to proceed.

Native acceptance is representative by item/room/service class, not exhaustive across every decoration, permission combination, house alias or packet branch. [Current status](STATUS.md) records the boundaries of completed checks and any final acceptance still pending.

Housing pet controls are available for the admitted upright Holgresh profile. The Live spider comparison establishes a command set but does not enable the unverified spider model. Pet behavior rates and restart defaults are documented emulator policies; see [pet controls](HOUSING-PETS.md).
