# Native RoF2 escrow duration and bulk withdrawal controls

The May 10, 2013 client sends Add Day (action 3), Add Week (4), and Withdraw All (7) through `OP_RealEstateEscrow`/0x2aa6. Each request has the existing 23-byte empty shape: estate ID, component zero, two empty strings, flag zero, opaque word zero, and no values. The Add Day and Add Week Notify branches construct the default action and set only action/current yard ID; they do not read a duration spinner or select a wallet. Responses preserve the original action and send no cursor value. The native response reader performs no cursor assignment for these actions. Authoritative balances continue through the estate snapshot, and `OP_MoneyUpdate` carries the resulting carried wallet.

The packet does not prove Live's funding account. This implementation therefore requires an explicit compatibility policy: `housing_escrow_bulk_policy`, matching the current ownership generation, native plot, catalogue revision, enabled flag, nonempty review reference, and mode 1. Installing the optional schema enables no property. Future paid purchase reviews may explicitly set `housing_upkeep_enrollment_policy.allow_bulk_carried_copper=1`; the existing purchase transaction then creates the exact newly acquired estate/native/catalogue bulk policy with contract/selection/rounding/reactivation. This flag defaults to zero, and a legacy schema without the column reads as false. Existing estates are not enrolled. A bounded `enrollment:` review reference preserves short reviews or records SHA-256 of longer reviews. Mode 1 uses carried copper value only, with deterministic denomination normalization. Bank, shared bank, cursor money, alternate currency, and item currency are never fallback funding accounts. An occupied item or coin cursor refuses the request.

Add Day deposits one full current daily upkeep cost into escrow. Add Week deposits seven full daily costs. Existing escrow is retained; the buttons do not rewrite the billing clock or directly buy an expiry date. Cost is derived under the actual transaction from the selected plot upkeep component plus currently placed billable house/furniture/interior obligations, using the same custody, room, house, catalogue, storage, and content witnesses as hourly billing. Stored and packed items contribute no charge. Unsupported currencies, unknown components, unresolved inventory applications, unsupported graph shapes, and arithmetic overflow refuse before commit. No partial-funding order is invented. Withdraw All transfers the entire copper escrow balance into the carried wallet, with current owner/guild/withdraw permission checks and checked capacity. Empty balance refuses without a journal entry.

All sixteen character currency counters are locked and compared. Funding kind is server-only and separate from cursor transfers and occupied Move Out refunds. Bulk request binding version 4 and outcome version 3 record the original packet, exact wallet before/after, escrow before/after, daily amount, catalogue revision, and SHA-256 rate/review witness. Existing cursor binding/outcome versions and occupied-refund formats are unchanged. Known COMMIT retains the simulation fence through profile application and durable ACK; historical acknowledged receipts cannot reapply an old wallet. Fresh-connection resolution validates the immutable receipt after uncertain COMMIT.

Certified writer-death reconciliation validates the exact inventory/custody linkage and bulk receipt, actual committed currency, empty cursor, and immutable binding. It writes a separate bulk death audit and clears the stale pending reservation for a fresh DB load. It does not debit again or claim that dead-process memory was applied; the original receipt retains `applied=0`. Ordinary legacy cursor death recovery retains its earlier fail-closed behavior.

Representative native acceptance completed personal Add Day, Add Week, Withdraw All and insufficient-funds refusal, plus paid guild purchase, automatic enrollment and guild Add Day. Two genuine world assessments charged 83 copper each. The same open finance window automatically refreshed from 1917 to 1834 copper after the second assessment without reopening or another action. The reconstructed guild frame opened Plot Search. These representative observations do not certify every graph, item, catalogue, historical Live policy or guild variant.

World billing invalidation uses the existing internal `ServerOP_HousingUpkeepRefresh`. Modern Servertalk pads an empty message to one zero byte. Publishers send that canonical byte explicitly, and authenticated receivers accept byte0 or the legacy empty shape, rejecting all other payloads. This preserves post-assessment native estate/escrow refresh without changing client protocol or financial accounting.
